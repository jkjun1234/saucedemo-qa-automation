# TC04 우편번호 누락 — AI 검증

2026-10-29, 현재 자동화 단계 작성·사이트 관찰·실행·엑셀 저장은 AI(Codex)가 수행했습니다. 과거 사용자 수동 확인과 이번 자동화 수행을 구분합니다.

## 관찰과 시나리오

실제 SauceDemo에서 상품1개를 담고 주문 정보 화면으로 이동해 가상 이름 Test / User를 입력하고 우편번호를 비웠습니다. Continue를 클릭한 결과:

- 오류 문구 `Error: Postal Code is required` 표시.
- 주소 `https://www.saucedemo.com/checkout-step-one.html` 유지.
- 이름 입력칸 표시, 우편번호 값은 빈 문자열.
- 주문 확인 컨테이너 `[data-test="checkout-summary-container"]`는0개.

의도한 필수 입력 차단이므로 **Pass**입니다. 서비스 결함 발견 사례가 아닙니다.

## 구현·검사

- 새 컨텍스트에서 자체 로그인·상품 추가·장바구니/주문 정보 화면 전환·가상 이름 입력·빈 우편번호 입력·Continue·오류 문구/화면 유지/주문 확인 화면0개를20단계로 작성했습니다.
- ‘입력’ 단계의 입력값이 빈 엑셀 셀이면 빈 문자열로 읽어 `fill("")`을 수행합니다. 행 전체를 건너뛰지 않습니다. 기존 실행기 동작을 재사용했고 `step_runner.py`·`excel_io.py`는 수정하지 않았습니다.
- TC04 실행 단계 부재로 새 사이트 검사가 먼저 실패했고, 단계 준비 후 실제 사이트에서 통과했습니다.
- 최종 전체 검사 **57 passed in24.59s**: 개발52개+사이트 검사5개(TC01 기존/새 방식·TC02·TC03·TC04). 서로 다른 업무 시나리오는4개입니다. `pytest.log`, `pytest.xml`에 보관했습니다.
- 별도 실제 Chromium 실행 `20261029_203210_7283e932`: TC04 20단계 완료·Pass·선택한 파일 저장 성공. `tc04-events.jsonl`, `tc04-summary.json`에 기록했습니다. headless=True이며 GUI에서 사용자가 직접 시작한 실행은 아닙니다.

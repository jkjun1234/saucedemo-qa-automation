## 실제 사이트 확인

`SauceDemo_TC_실행용_v2.xlsx`에서 TC01을 읽어 새 `step_runner.run_cases()`로 실행했습니다. 접속·아이디 입력·비밀번호 입력·클릭·URL확인·상품 표시·최소개수확인의 7단계가 끝났고 TC01 Pass를 확인했습니다. [실제 실행 이벤트](tc01-events.jsonl)에 단계별 시작/종료와 판정이 있습니다. 입력값 자체를 일반 단계 로그에 출력하지 않습니다.

엑셀은 읽기만 했습니다. 결과/비고 자동 기록은 다음 작업이며, 실행용 엑셀에 Pass를 기입한 결과가 아닙니다.

## 개발 검증과 전체 결과

- 새 로컬 검사 7개: 동작 수행·진행 이벤트, Fail 뒤 다음 TC의 깨끗한 상태, 실패 증거 저장, 단계 사이/동작 대기 중 중지, 잘못된 주소 차단, 엑셀 입력/기대값 변경에 따른 실제 동작·판정 변화, 닫힌 브라우저의 환경 오류 구분.
- 로컬 연습 화면에서 엑셀 입력 alice→bob 변경으로 실패하고 기대 URL을 bob에 맞추면 통과함을 확인했습니다. 이 가상 TC들은 실제 SauceDemo 업무 TC 완료 건수에 넣지 않습니다.
- 전체 [pytest.log](pytest.log)·[pytest.xml](pytest.xml): `30 passed in 14.86s`. 개발용 28개와 같은 SauceDemo TC01의 새 방식·기존 방식 사이트 검사 2개입니다. TC02~05 완료 실적이 아닙니다.

## 확인한 문제와 수정

1. 새 실행기 검사 4개는 구현 전 모듈 부재로 실패했고 구현 후 통과했습니다.
2. 전체 실행에서 기존 pytest-playwright 세션 다음에 새 동기 실행기를 같은 스레드로 시작하면 `Playwright Sync API inside the asyncio loop` 오류가 났습니다(4 failed, 24 passed). 프로그램의 계획된 구조처럼 작업 스레드에서 새 실행기를 호출하도록 검사 보조를 수정했습니다.
3. 읽기 전용 코드 검토에서 대기 도중 중지를 Fail로 분류하는 문제와 닫힌 브라우저를 업무 Fail로 분류하는 문제가 확인됐습니다. 두 재현 검사가 실제로 실패함을 확인하고 중지=N/A, 브라우저 종료=환경 오류로 수정한 뒤 전체 검사를 통과했습니다.

브라우저/설정 문제를 서비스 결함 발견으로 쓰지 않습니다. 위 수정은 실행 프로그램의 판정 처리 개선이며, 별도로 계획한 모호한 버튼 선택·Trace 분석 실습의 완료로 계산하지 않습니다.

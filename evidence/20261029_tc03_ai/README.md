# TC03 상품 추가·삭제 — AI 검증

2026-10-29, 단계 작성·브라우저 관찰·코드 검사·결과 저장은 AI(Codex)가 수행했습니다. 사용자 직접 실행·설명 완료를 뜻하지 않습니다.

## 시나리오와 구현

실행용 엑셀에 TC03 19단계를 추가했습니다. `step_runner.py`와 `excel_io.py` 코드는 변경하지 않았고 기존 접속·입력·클릭·URL확인·표시확인·문구확인·개수확인을 재사용합니다. TC03은 새 컨텍스트에서 자체 로그인하며 TC01 성공에 의존하지 않습니다.

1. 정상 로그인과 상품 목록 URL, 추가 전 수량 배지0개 확인.
2. Sauce Labs Backpack 추가 후 수량 배지1 확인.
3. 장바구니 URL과 장바구니 화면 표시 확인.
4. 상품 행1개, 상품명 Sauce Labs Backpack, 상품 수량1 확인.
5. 상품 삭제 후에도 장바구니 URL·화면이 유지되는지 확인.
6. 상품 행0개와 수량 배지0개 확인.

삭제 후 빈 페이지나 다른 화면으로 이동했는데 요소 개수만0개여서 통과하는 것을 피하려고 장바구니 URL·컨테이너도 다시 검증합니다.

## 실제 관찰 중 발생한 스크립트 문제

- 사전 관찰 스크립트가 장바구니 클릭 직후 상품명을 바로 읽다가 같은 선택자가 상품6개에 일치하는 strict mode 오류를 냈습니다.
- 후속 관찰에서는 주소가 이미 `/cart.html`인데 상품명 요소는 아직6개인 순간이 확인됐습니다. URL 이동만으로 화면 내용의 전환 완료를 보장할 수 없었습니다.
- 장바구니 컨테이너 `[data-test="cart-list"]` 표시까지 기다리자 상품1개·상품명·수량1·배지1을 확인했습니다. 삭제 후 상품0개·배지0개·장바구니 화면 유지도 관찰했습니다.
- TC03에 URL확인 후 컨테이너 표시확인을 넣었습니다. `.first`로 모호성을 숨기거나 임의의 고정 대기시간을 넣지 않았습니다.
- 이는 AI 사전 관찰 중의 스크립트 전환 확인 문제입니다. SauceDemo 서비스 결함이나 사용자 직접 발견·수정 실적으로 쓰지 않습니다. 이 사전 오류의 Trace는 보관하지 않았으므로 Trace로 분석했다고 쓰지 않습니다. 계획된 별도 Add to cart 선택자 오류 분석 실습의 완료로 대체하지 않습니다.

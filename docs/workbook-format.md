# 엑셀 규격과 실행 결과

[프로젝트 소개로 돌아가기](../README.md)

## 두 시트의 역할

| 시트 | 필수 열 | 역할 |
|---|---|---|
| `TC_웹주문` | TC-ID, 테스트 시나리오, 결과, 비고 | 사람용 TC 목록과 결과 |
| `자동화_실행단계` | TC-ID, 순서, 동작, 대상, 입력값, 기대값, 설명 | 실행기가 읽는 동작·검증 순서 |

열은 이름으로 찾습니다. 단계가 준비된 TC를 읽으며 과거 결과는 새 실행 판정에 사용하지 않습니다. 상세 입력 검사 규칙은 [excel_io.py](../excel_io.py)를 참고하세요.

## 지원 동작

| 동작 | 대상 | 입력값 | 기대값 |
|---|---|---|---|
| 접속 | 비움 | 상대 경로, 빈칸은 기본 주소 | 비움 |
| 입력 | 요소 선택자 | 입력 문자열, 빈칸은 입력 지우기 | 비움 |
| 클릭 | 요소 선택자 | 비움 | 비움 |
| URL확인 | 비움 | 비움 | 대상 주소 기준 상대 경로 |
| 표시확인 | 요소 선택자 | 비움 | 비움 |
| 문구확인 | 요소 선택자 | 비움 | 전체 기대 문구 |
| 개수확인 | 요소 선택자 | 비움 | 0 이상의 정확한 개수 |
| 최소개수확인 | CSS 선택자 | 비움 | 1 이상의 최소 개수 |
| 문구저장 | 읽을 요소 선택자 | 저장 이름 | 비움 |
| 금액저장 | 읽을 요소 선택자 | 저장 이름 | 비움 |
| 저장문구확인 | 비교할 요소 선택자 | 앞서 저장한 이름 | 비움 |
| 저장금액확인 | 비교할 요소 선택자 | 앞서 저장한 이름 | 비움 |

`최소개수확인=1`은 2개여도 통과하지만 `개수확인=1`은 정확히 1개여야 합니다. 문구 비교에는 Playwright의 공백 정규화 규칙이 적용됩니다. 저장 이름은 화면 입력 문자열이 아니며, 같은 TC에서 먼저 저장해야 비교할 수 있습니다. 저장값은 다음 TC에서 초기화합니다.

## 판정과 저장

- **Pass:** 모든 실행·검증 단계 통과. 이전 실패 비고는 지웁니다.
- **Fail:** 단계 실행 또는 검증 실패. 실패 단계·사유와 수집 가능한 증거를 남깁니다. 제품 결함 확정과는 구분합니다.
- **N/A:** 사용자 중지·실행 환경 문제 등으로 완료하지 못한 TC. 사유를 남깁니다.

선택한 같은 엑셀의 결과·비고를 갱신하며 결과 사본·새 결과 시트를 만들지 않습니다. 실행 대상이 아닌 행은 유지합니다. 파일이 열려 있어 저장할 수 없으면 실행 판정과 별도로 저장 실패를 표시합니다.


기존 [설계서 초안](../SauceDemo_TC_설계서_초안.xlsx)은 학습 기록 보존용입니다. [양식 준비 도구](../tools/prepare_tc_workbook.py)는 최초 실행용 파일 준비에 사용하며 이미 존재하는 실행용 파일은 덮어쓰지 않습니다.

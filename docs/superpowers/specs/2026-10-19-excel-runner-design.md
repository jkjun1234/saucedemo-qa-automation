# 엑셀 절차 기반 자동화 실행 프로그램 — 승인된 설계

상태: 2026-10-19 사용자가 이 계획으로 다음 작업 시간에 1단계부터 시작하는 ①안을 선택하여 승인했다. 설계·계획 승인 기록이며 프로그램 구현 완료 문서가 아니다.

2026-10-20 최종 사용자 변경: 선택한 TC 파일의 `TC_웹주문` 표에서 기존 `결과` 열에 Pass/Fail/N/A를, 기존 `비고` 열에 Fail·N/A 사유와 증거 경로를 기록한다. `실제 결과` 열은 실행용 양식에서 제거한다. 별도 사유·증거·실행정보 열, 결과 사본·결과 시트를 추가하지 않는다. 아래 저장 규칙을 이 요청에 맞게 정정했으며 오늘 실제 엑셀은 수정하지 않는다.

## 사용자와 확인한 요구

- 프로그램에서 TC 엑셀 파일과 대상 주소를 지정하고 시작 버튼으로 실행한다. 대상은 우선 SauceDemo다.
- 실행 절차는 엑셀에 접속·입력·클릭·검증 단계로 작성한다. 지원하는 동작의 순서·대상·값은 엑셀에서 바꿀 수 있다(B안).
- 상단에 파일·주소·시작/중지·현재 TC를 표시하고, 아래에 `TC 목록·진행 / 실행 결과 / 상세 로그` 세 탭을 둔다(A안).
- 한 TC가 실패하면 그 TC를 Fail로 기록하고, 새 브라우저 상태에서 다음 TC를 계속 실행한다(A안). 실패한 TC의 남은 단계는 실행하지 않는다.
- TC01 → TC02 → TC03 → TC04 → TC05 순으로 작성·검토한다. 개발용 검사를 실제 TC 집계에 넣지 않는다.
- AI가 기능 하나씩 작성·검증·설명·한국어 커밋·푸시한다. 사용자 직접 수행은 확인한 경우에만 기록한다.
- 기존 TC의 시나리오·절차·예상 결과와 기존 실행 증거를 보존하고 각 소스 파일 최상단에 역할을 설명한다. 선택한 TC 파일의 `결과`·`비고`는 이번 실행 값으로 갱신한다.

## 첫 버전의 경계

- Windows, Python 3.12, Playwright 동기 API, Chromium, openpyxl. 창은 기존 환경에서 import를 확인한 tkinter/ttk를 제안한다. 창 기동·사용성은 아직 검증하지 않았다.
- SauceDemo와 합의한 엑셀 한 가지 양식에 한정한다. 임의의 회사 양식·자유로운 한글 절차·카메라 장비를 자동 해석한다고 표현하지 않는다.
- 새로운 종류의 동작·양식·장비별 대상 선택은 Python 또는 변환 규칙 추가가 필요하다.
- 테스트 대상 제품 개발, 여러 브라우저, CI, 실행 파일 배포 패키징은 첫 버전에 포함하지 않는다. 프로그램 실행용 스크립트와 안내를 제공한다.

## 엑셀 구조 — 제안

- 실행용 양식 준비 단계에서 TC01~05를 번호순으로 정리하고 `실제 결과` 열을 제거한다. 그 외 기존 TC 설명 열과 `결과`·`비고`를 유지한다. 실행 시에는 사용자가 선택한 TC 파일 자체를 갱신하며 결과 사본은 만들지 않는다. 양식 정리는 아직 미수행이다.
- `자동화_실행단계`: `TC-ID / 순서 / 동작 / 대상 / 입력값 / 기대값 / 설명`. 기존 단계 시트의 작성 내용은 원본에 보존하고 작업본에서 완성한다.
- `대상`은 우선 CSS 선택자 한 가지 방식으로 통일한다. UI 이름을 자유롭게 적으면 자동으로 찾는 기능은 포함하지 않는다.
- 대상 주소는 http/https를 포함해야 한다. `접속` 동작의 `입력값`은 상대 경로이며 빈칸이면 입력한 기본 주소로 이동한다. `대상`은 비운다. URL확인의 `기대값`은 `/inventory.html`처럼 경로를 적어 대상 주소와 조합한다. 단계에 로그인 성공 주소를 넣어 로그인을 건너뛰지 않는다.
- `입력` 동작의 빈 입력값은 빈 문자열로 처리한다. 빈칸을 지우거나 우편번호를 비우는 검증에 사용할 수 있으며, 비어 있다고 누락 오류로 처리하지 않는다. 동작마다 필요한 열·값의 검증 규칙을 구분한다.
- 첫 동작: `접속`, `입력`, `클릭`, `URL확인`, `표시확인`, `최소개수확인`. 이후 TC에서 필요할 때만 `문구확인`, `개수확인`, `값저장`, `저장값비교`를 추가한다.
- `값저장`은 현재 TC의 메모리에 이름으로 값을 보관하고, `저장값비교`는 현재 요소 값과 비교한다. TC05 상품·수량·소계 비교에 사용하며 TC 간 값을 공유하지 않는다. 초기 비교는 텍스트의 앞뒤 공백 제거·금액 기호와 소계 라벨 제거 등 명시한 값 종류에만 적용한다.
- 단계 순서 누락·중복, 지원하지 않는 동작, 필요한 대상/값 누락은 시작 전 오류로 표시한다. 임의 Python 코드·수식을 실행하지 않는다.
- 기존 `자동화_데이터`와 초기 읽기 연습은 보존한다. 새 실행 단계의 값 공급과 중복 관리하는 기능은 첫 버전에 추가하지 않는다.

## 프로그램 흐름 — 제안

1. 파일과 대상 주소를 입력한다. 기본 주소는 https://www.saucedemo.com/ 이다.
2. 파일을 읽어 실행 단계가 준비된 TC와 검증 오류를 표시한다. 사람용 표에만 있는 TC를 준비 완료나 Pass로 표시하지 않는다. 첫 작업본의 실행 대상은 TC01 하나로 한정하고 준비 범위를 명시한다.
3. 시작하면 창은 응답을 유지하며, 별도 작업 스레드에서 Playwright를 시작한다. 창 갱신은 메인 스레드에서 큐로 전달받아 처리한다.
4. TC마다 새 브라우저 컨텍스트를 만든다. 현재 TC·단계·수행 동작을 즉시 알리고 결과가 결정되는 대로 목록과 결과 탭에 반영한다.
5. 검증 불일치나 단계 실행 오류가 나면 그 TC는 Fail, 실패 단계·기대/실제·이유를 남긴다. 오류 종류(검증/요소 조작/환경)를 로그에 구분한다. 그 TC의 남은 단계는 건너뛰고 다음 TC로 간다.
6. 브라우저 시작 불가 등 전체 실행이 불가능한 환경 오류는 전체를 멈추고 이유를 보여준다. 미실행 TC를 서비스 Fail이나 Pass로 오인하게 만들지 않는다.
7. 중지 요청은 현재 동작의 종료/제한시간 뒤 다음 단계 전에 반영한다. 실행 중이던 TC가 미완료면 N/A와 중지 사유를 남기고, 새 TC를 시작하지 않는다. 브라우저를 정리한 후 다시 실행할 수 있어야 한다. 동작 제한시간은 기본 10초, 자동 재시도 없음.
8. 정상 종료·중지·실행 오류 뒤 이번 실행 결과는 선택한 TC 파일에 갱신하고, 로그·스크린샷·Trace는 실행별 경로에 저장한다. 파일이 열려 있거나 권한 문제로 저장할 수 없으면 화면에 저장 오류를 표시한다.

## 탭과 표시 정보

- 상단: TC 파일 찾기, 대상 주소, 시작/중지 버튼, 현재 TC/단계, 완료 건수.
- TC 목록·진행: TC-ID, 시나리오, 준비 여부, 진행 상태(대기/실행 중/완료/중지), 결과.
- 실행 결과: TC-ID, Pass/Fail/N/A, 기대 결과, 실제 결과·이유, 실패 단계, 증거 경로.
- 상세 로그: 시각, TC-ID, 단계 번호, 동작, 진행/오류 메시지. 대기 중에도 창이 멈추지 않아야 한다.
- 수행자는 실행 기록에 별도 입력하며 기본은 `미기록`이다. 프로그램이 사람인지 AI인지 자동으로 추정하지 않는다.

## 결과와 증거

- 선택한 TC 엑셀 파일 자체를 열어 기존 `TC_웹주문` 표에서 TC-ID가 일치하는 행의 결과를 갱신한다. 실행 결과용 엑셀 사본과 별도 `자동화_실행결과` 시트는 생성하지 않는다.
- 열 문자에 고정하지 않고 헤더 이름으로 `결과`·`비고` 열을 찾는다. TC-ID로 해당 행을 찾아 `결과`에 Pass/Fail/N/A를 쓴다. `실제 결과` 열은 사용하지 않으며 실행용 양식에서 제거한다.
- Fail·N/A이면 `비고`에 사유·실패 단계·필요한 기대/관찰 내용과 로그·스크린샷·Trace 경로를 기록한다. 없는 증거를 있다고 쓰지 않는다. Pass로 바뀐 TC에는 이전 실행의 실패·미실행 비고가 남지 않도록 비고를 비운다.
- 별도 `사유`·`증거`·실행 메타데이터 열은 추가하지 않는다. 실행ID·일시·수행자 등 추적 정보는 실행별 로그에 남긴다.
- 이번 실행 대상 TC의 결과·실행 메타데이터는 이번 값으로 갱신하며 과거 Pass를 재사용하지 않는다. 실행 대상으로 잡혔으나 중지 등으로 미실행한 TC에는 N/A와 사유를 쓴다. 실행 대상이 아닌 TC 행은 변경하지 않고, 그 행의 과거 결과도 이번 실행 집계에 넣지 않는다.
- TC-ID로 행을 찾아 기록하므로 행 순서에 의존하지 않는다. 중복 TC-ID·표에 없는 TC-ID 결과를 발견하면 잘못된 행에 쓰지 않고 저장 오류를 표시한다.
- Pass는 준비된 검증 단계가 모두 통과했을 때만 허용한다. 검증 단계가 없는 TC는 실행 준비 오류다. N/A에는 미실행·중지 등 사유를 함께 남긴다.
- 실행별 UTF-8 로그를 저장하고, 실패한 TC의 스크린샷·Trace를 보관한다. 같은 날 재실행해도 이전 결과를 덮어쓰지 않는다.
- 개발용 검사는 별도 폴더·명령으로 실행한다. 프로그램 시작 버튼은 전체 pytest 수집을 호출하지 않으며, 엑셀에 준비된 업무 TC만 실행한다.

## 첫 구현과 전체 완료 기준

첫 구현: TC01 하나를 사용해 파일 선택 → 주소 적용 → 엑셀 단계 실행 → 3개 탭 갱신 → 결과 파일 저장을 끝까지 확인한다. 코드 수정 없이 엑셀의 입력값 또는 기대값을 바꿨을 때 실행·판정이 달라지는지도 확인한다.

전체: TC01~05 각각의 절차·검증·결과가 연결되고, TC 실패 후 다음 TC가 새 상태에서 실행된다. 중지·재실행·원본 보존·증거 저장을 확인하고 사용자가 직접 전체 실행 및 핵심 흐름을 설명한다. 의도적 스크립트 오류 분석·개선 사례는 일반 실행용 작업본과 분리한다.

## 일정·기여도

- 기존 6~8시간 추정은 새 UI·단계 실행기 범위에 그대로 적용하지 않는다. 첫 TC01 전체 흐름이 끝난 뒤 남은 시간을 다시 계산한다. 기존 누적 8시간 점검 규칙은 유지하며 실제 누적은 미확인이다.
- 다음 작업 블록은 TC01 전체 흐름을 향한 작은 기능 단위로 진행한다. 첫 블록에 모두 완성된다고 약속하지 않는다.
- 지원 준비를 GUI 확장 때문에 계속 늦추지 않는다. 첫 버전 이후 디자인 장식·장비 확장·배포 패키징을 추가하지 않는다. 지원일은 여전히 미확정이며 마감은 사용자 확인 기준 11/6이다.
- AI 작성·실행과 사용자 검토·직접 실행·수정을 실행별로 구분한다. 계획이나 AI 결과를 사용자 실적으로 바꾸지 않는다.

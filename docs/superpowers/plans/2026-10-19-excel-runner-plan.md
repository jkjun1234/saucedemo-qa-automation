# 엑셀 절차 기반 자동화 실행 프로그램 구현 계획 — 승인됨

> **구현 담당:** 사용자가 선택한 방식대로 현재 대화의 AI가 기능 하나씩 구현·검증·설명한다. 구현 시 superpowers:executing-plans를 적용한다. 2026-10-19 사용자가 ① 이 계획으로 다음 작업 시간에 1단계부터 시작을 선택하여 승인했다. 당일 23:15에는 정리·종료하며 구현은 다음 작업 시간에 시작한다.

**목표:** TC 파일·대상 주소·시작 버튼으로 엑셀 절차를 실행하고 TC별 진행·결과·로그를 표시하며 선택한 TC 파일에 결과를 갱신한다.

**구조:** 엑셀 읽기/결과 저장, 단계 실행, 창 표시를 분리한다. GUI는 엑셀에 준비된 TC만 단계 실행기에 전달하며 개발용 pytest 검사를 섞지 않는다. 기존 TC01 코드는 선택자·검증의 참고 및 이전 실행 증거로 보존한다.

**도구:** Python 3.12, tkinter/ttk, Playwright 동기 API, Chromium, openpyxl, pytest(개발 검증용).

**설계 기준:** [설계 초안](../specs/2026-10-19-excel-runner-design.md). 동작 명칭·엑셀 열·실패/중지 정책·기여도 기준은 설계를 따른다.

**2026-10-20 최종 결과 열 변경:** 선택한 TC 파일 자체에서 기존 `결과`에 Pass/Fail/N/A, 기존 `비고`에 Fail·N/A 사유와 증거 경로를 기록한다. `실제 결과` 열은 실행용 양식에서 제거한다. 사유·증거·실행정보 열, 결과용 사본·별도 결과 시트를 추가하지 않는다. 이전의 결과 사본·별도 열 추가 지침을 폐기한다.

## 공통 조건

- 기존 서류·실행 증거와 TC의 시나리오·절차·예상 결과 보존. 실행용 양식에서 실제 결과 열을 제거하고 결과·비고 열을 사용한다. 매 실행은 선택한 TC 파일을 직접 갱신한다.
- 모든 Python 파일 최상단에 역할과 사용하는 파일을 설명한다.
- TC01→02→03→04→05 순으로 확장한다. 한 기능마다 검증·설명·한국어 커밋·푸시.
- 업무 시나리오 건수와 개발용 검사 건수는 항상 따로 집계한다.
- 자동 재시도 없이 실제 실패를 남긴다. 단계 실행기는 지원 동작만 처리한다.
- 10/19~20에는 계획만 작성했다. 10/28 작업 1 구현을 시작했으며 작업 블록·종료 규칙을 따른다. 이력과 현재 구현 상태를 구분한다.

## 파일별 책임

| 파일 | 역할 |
|---|---|
| `app.py` (신규) | 창·파일/주소 입력·탭 표시·작업 스레드와 큐 연결 |
| `excel_io.py` (신규) | 실행 단계 읽기·양식 검사·선택한 TC 파일의 결과 영역 갱신 |
| `step_runner.py` (신규) | 동작별 Playwright 실행·TC 상태 분리·이벤트·중지·실패 증거 |
| `tests/unit/` | 임시 엑셀·동작 처리·결과 저장 등 개발용 검사 |
| `tests/e2e/` | 실제 SauceDemo의 TC 실행 확인. 개발용 결과와 별도 보고 |
| `examples/` | 기존 학습 코드·이전 TC01 코드 보존 및 설명 |
| `SauceDemo_TC_실행용_v2.xlsx` | 번호순 사람용 TC와 구조화한 실행 단계 |

기존 파일 이동은 역할 설명과 import 변경을 함께 검증하고 Git 이력을 보존한다. 기존 `tc_data.py`는 입력값 읽기 학습 코드로 보존하며 새 단계 실행기로 오인하게 하지 않는다.

## 경계 인터페이스

- `excel_io.read_cases(path: Path) -> list[dict]`: `tc_id`, `scenario`, `steps`를 반환. 단계 키는 `order/action/target/value/expected/description`. 잘못된 파일은 구체적인 행·열 사유가 있는 ValueError.
- `step_runner.run_cases(cases, base_url: str, emit, stop_event) -> list[dict]`: TC-ID별 결과를 반환. `emit(dict)`로 `tc_started/step_started/step_finished/tc_finished/run_finished` 이벤트를 보냄. 결과에는 `tc_id/status/expected/actual/failed_step/reason/started_at/finished_at/evidence`가 있음.
- `excel_io.write_results(source: Path, run_dir: Path, results: list[dict], operator: str) -> Path`: source에서 헤더 이름으로 결과·비고 열을 찾고 TC-ID로 행을 찾아 갱신한 뒤 같은 경로를 반환한다. 결과에는 Pass/Fail/N/A, 비고에는 Fail·N/A 사유·증거를 쓴다. Pass면 이전 실패 비고를 지운다. 실행정보는 run_dir 로그에 기록하며 새 열·결과 사본·별도 결과 시트를 만들지 않는다.
- `app.py`는 시작 전 파일 검증 후 작업 스레드에서 실행·저장을 호출하고 메인 스레드에서 큐 이벤트를 그린다. 브라우저 객체를 UI 스레드에서 조작하지 않는다.

## 집중 확인할 실패 조건

1. 잘못된 TC 양식·동작·검증 없는 TC: 브라우저 시작 전에 중단하고 위치·이유 표시(작업 1).
2. 대상 주소를 바꿨는데 코드의 SauceDemo 고정 주소로 접속함: 입력 주소를 실행의 기준으로 사용(작업 2).
3. 첫 TC 실패 또는 중지로 창이 멈추거나 다음 TC가 오염됨: 새 컨텍스트·중지 이벤트·UI 큐 검증(작업 2~3).
4. 과거 Pass나 개발용 검사 결과가 이번 업무 결과에 포함됨: 실행별 초기화·업무 TC 집계만 사용(작업 1~3).
5. 파일 잠금·저장 권한 문제: 같은 TC 파일에 저장 실패를 표시하고 성공으로 숨기지 않음. 실행 증거 폴더는 실행마다 분리(작업 3).

## 범위와 시간 점검
